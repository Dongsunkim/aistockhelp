# 가격·자료 조건 감시 서버

웹 분석 화면과 별도로 **계속 실행되는 감시 서버**가 필요합니다. Vercel 함수와 브라우저의 주기적 조회만으로는 앱을 닫은 동안 감시하지 못합니다. 이 구현은 날짜·시각이 있는 KIS 분봉 시세를 조회하고, 주기 완료 후 기본 15초를 기다린 뒤 다시 확인합니다. 조회·전송에 걸리는 시간이 더해져 실제 간격은 길어질 수 있습니다. 거래소 체결 스트림이 아니므로 짧게 가격대를 통과한 경우 놓칠 수 있습니다. 모든 체결의 순간 포착에는 별도의 실시간 WebSocket 시세 연결이 필요합니다.

## 실행과 연결

1. 영구 디스크를 사용할 수 있는 상시 실행 호스트에 저장소를 배포합니다. `Dockerfile.monitor`를 사용하거나 `uvicorn monitor_service:app --host 0.0.0.0 --port 8080 --workers 1`로 실행합니다. 호스트 프로세스는 하나만 실행합니다.
2. 감시 호스트의 보안 환경변수에 `ALERT_ACCESS_TOKEN`(예측 불가능한 24자 이상 문자열), `SIGNAL_ALERT_DB=/data/alerts.sqlite3`, `KIS_APP_KEY`, `KIS_APP_SECRET`을 등록합니다. `/data`에는 재배포·재시작 후에도 유지되는 영구 디스크를 연결합니다. 데이터베이스를 임시 파일시스템에 두면 규칙과 중복 방지 이력이 사라집니다.
3. 국내 공시 대조에는 `DART_API_KEY`를 등록합니다. 모바일 전달에는 본인의 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`를 등록합니다. 키는 채팅·소스·브라우저 공개 코드에 넣지 않습니다. 미설정한 전달 채널은 연결된 것처럼 표시하지 않습니다.
4. 감시 호스트에 HTTPS 주소를 부여합니다. Vercel 웹앱 환경변수에는 `ALERT_SERVICE_URL=https://감시호스트주소`만 등록합니다. 감시 호스트 자신에게는 이 변수를 설정하지 않습니다. Vercel에 감시용 접근키를 넣어 모든 방문자에게 대신 인증해 주지 않습니다.
5. 웹 화면의 개인 알림 연결란에 `ALERT_ACCESS_TOKEN`을 입력합니다. 공개 분석 기능과 별개로 개인 알림 규칙·이력에만 접근키가 필요합니다. `/api/alerts/status`의 최근 실제 감시 주기가 확인되어야 `worker_running=true`가 됩니다. 프로세스를 실행했다는 이유만으로 작동 중으로 표시하지 않습니다.

기본 외부 연결 대상은 한국투자증권 KIS, 네이버증권, OpenDART, FRED, Yahoo Finance와 선택한 텔레그램입니다. 실행 호스트의 네트워크 정책에서 필요한 HTTPS 연결을 허용해야 합니다. 브라우저가 아닌 감시 서버가 자료를 조회합니다. 환경변수 설정만으로 제공처의 사용 권한과 최신성 검증이 완료되지는 않습니다.

### 모바일에서 Render로 배포하는 경우

저장소의 `render.yaml`은 감시 서버 한 개와 1GB 영구 디스크 구성을 제공합니다. Render에서 **New → Blueprint**로 이 GitHub 저장소를 연결하고, 제시된 호스트·디스크 요금과 환경변수 설정을 확인한 뒤 배포할 수 있습니다. 상시 실행과 영구 디스크가 필요한 유료 구성 초안이며 이 파일을 추가하는 것만으로 서비스 생성이나 과금이 시작되지는 않습니다.

Blueprint가 생성한 `ALERT_ACCESS_TOKEN`은 Render 서비스의 Environment에서 본인만 확인하고 웹앱의 개인 알림 연결란에 입력합니다. 배포 후 Render의 HTTPS 서비스 주소를 Vercel의 `ALERT_SERVICE_URL`로 등록하고 웹앱을 재배포합니다. 텔레그램을 쓸 경우 감시 서버 Environment에 본인의 봇·채팅 설정을 추가합니다. `/api/alerts/status`에서 작동 여부가 확인되기 전에는 알림이 활성화된 상태가 아닙니다.

## 알림 의미와 검증

- 매수 관찰은 지정한 가격 구간 진입과 서버가 다시 수집한 주가·재무·기사·공시·미국 금리·환율·물가·주요 주식 조건을 함께 확인합니다. 누락·오래된 자료·위험 신호가 있으면 매수 알림을 보류합니다. 기사·리서치의 원문 내용까지 검증했다는 뜻은 아닙니다.
- 판단 근거는 가격 감시와 별도로 수집합니다. 최초 등록 직후에는 근거가 준비될 때까지 매수 알림을 보류하고, 이후 주기에서 검증된 근거와 최신 시세를 함께 확인합니다. 통과한 근거는 5분 동안 재사용하되 원래 검증 시각을 유지하고, 미충족 근거는 짧은 간격으로 다시 수집합니다.
- 매도·손절 관찰은 사용자가 정한 가격 기준의 도달 사실을 알립니다. 주문을 실행하지 않습니다.
- 분봉 시각과 거래일이 확인되고 60초 이내인 국내 공식 시세만 장중 조건 평가에 사용합니다. 분봉 시각은 개별 체결 틱의 시각과 다릅니다. 미국 지연 시세와 시각이 없는 국내 REST 응답은 자동 가격 도달 알림을 생성하지 않습니다.
- 같은 조건 안에 계속 머무르면 반복 알림을 만들지 않습니다. 유효한 시세가 조건 밖으로 나온 뒤 다시 진입해야 새 알림을 만듭니다. SQLite에 규칙·상태·이력을 보관하여 프로세스 재시작 후에도 유지합니다.
- 앱 내 이력 생성과 텔레그램 전달 성공은 구분합니다. 전달 실패는 재시도하되, 시세 관측 후 120초가 지난 알림은 전송 기한 만료로 기록하고 뒤늦게 보내지 않습니다. 외부 서비스가 수신한 직후 프로세스가 중단되면 성공 기록을 남기기 전에 종료되어 재시도 시 같은 메시지가 전달될 수 있습니다. 전달 경로는 최소 한 번 방식이며 정확히 한 번 전달을 보장하지 않습니다. 감시를 중지·삭제하면 대기 중인 전송을 취소하지만 이미 진행 중인 외부 전송은 회수할 수 없습니다.

## API

공개 연결 상태: `GET /api/alerts/status`.

아래 API에는 `Authorization: Bearer <개인 접근키>`가 필요합니다.

- `GET /api/alerts/rules`: 개인 규칙 목록
- `POST /api/alerts/rules`: `symbol`, `name`, `market`, `action`, `enabled`와 가격 저장. `buy_zone`은 `lower`와 `upper`, `sell_above`·`stop_below`는 `threshold` 사용
- `PATCH /api/alerts/rules/{id}`: `{ "enabled": false }`로 중지·재개
- `DELETE /api/alerts/rules/{id}`: 규칙 삭제
- `GET /api/alerts/events?limit=50`: 생성 이력과 전달 상태

규칙 저장이 감시 작동을 의미하지 않습니다. 마지막 감시 시각, 실제 시세 검증, 자료 충족 여부와 모바일 전달 설정을 각각 확인해야 합니다.
